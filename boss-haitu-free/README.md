# 一键投 Boss

一个 **Chrome / Edge MV3 浏览器扩展**,在 BOSS 直聘网页上批量投递岗位:自动打招呼、发送招呼语、自动发简历,并可按职位名、工作地、招聘者活跃状态筛选。

所有数据(设置、投递记录)只保存在你本地浏览器里,代码全部本地运行,不依赖任何服务器。

**制作人:王智纬 / wangzhiwei**

## 功能

| 功能 | 说明 |
|---|---|
| 一键批量投递 | 打开职位列表页,自动滚到底加载全部职位,逐个点开 → 点「立即沟通」 |
| 暂停 / 继续 | 投递过程中可随时暂停、原地继续,不用重头再来 |
| 职位名筛选 | 只投职位名包含指定关键词的岗位(标签式输入) |
| 城市筛选 | 从下拉里挑城市,支持多选 |
| 薪资范围筛选 | 双滑块选薪资区间(如 15K–30K) |
| 公司规模筛选 | 按 0-20人 / 100-499人 / 1000人以上 等分档多选 |
| 招聘者状态筛选 | 只投「在线 / 今日活跃 / 3日内活跃 …」等指定状态的招聘者 |
| 排除猎头 | 跳过猎头职位 |
| 招呼语(多条) | 首次沟通时,依次发送多条自我介绍(建议 2~3 条) |
| 自动发附件简历 | 首次沟通后自动发送你的附件简历 |
| 追问自动发简历 | HR 回复里提到「简历」时,自动发送简历 |
| **图片发送** | 上传 png / jpg / jpeg / webp / gif,聊天时**作为图片消息**发给 HR(常用于图片简历、作品截图) |
| 图片自动触发 | 「首次沟通后自动发图片」/「HR 提到简历时发图片」两个开关 |

界面分三个底部 Tab:**首页**(数据卡 + 一键投递 + 筛选 + 实时投递日志)、**数据统计**(累计/今日/成功率、近 7 日趋势、状态分布)、**设置**(招聘者状态、投递偏好、招呼语、**聊天与简历**)。其中「聊天与简历」把**沟通/简历**与**图片发送**合并在一张卡里,分两个小节,底部一个 **开始聊天** 按钮统一启动。

## 安装

1. 打开 `chrome://extensions`(Edge 用 `edge://extensions`)
2. 打开右上角 **开发者模式**
3. 点 **加载已解压的扩展程序** → 选择本扩展目录(含 `manifest.json` 的那一层)
4. 打开任意 BOSS 直聘页面,页面右下角会出现「一键投」按钮,点击展开面板
   - 也可点击浏览器工具栏上的扩展图标来显示 / 隐藏面板

## 使用

### 一、批量投递(职位列表页)

1. 打开 [推荐职位页](https://www.zhipin.com/web/geek/jobs),或直接在 BOSS 里 **搜索** 出你想要的结果页
2. **首页 → 筛选条件** 里设置:岗位关键词、城市、薪资范围(拖动两端滑块)、公司规模
3. 切到 **设置** Tab,补充:招聘者活跃状态、是否排除猎头、操作间隔、招呼语
4. 回到 **首页**,点 **一键开始投递**;投递中可点旁边的 ⏸ **暂停 / 继续**,或 ⏹ **停止**

### 二、自动沟通 / 自动发简历(聊天页)

1. 打开 [聊天页](https://www.zhipin.com/web/geek/chat)
2. **设置** Tab → **聊天与简历** 卡片 → **沟通与简历** 小节里勾选:
   - 首次沟通发送招呼语
   - 首次沟通后自动发附件简历
   - HR 提到「简历」时自动发简历
3. 点卡片底部的 **开始聊天(聊天页)**

### 三、发图片(图片简历 / 作品图)

1. **设置** Tab → **聊天与简历** 卡片 → **图片(图片简历 / 作品图)** 小节 → 点 **选择图片**
2. 选 png / jpg / jpeg / webp / gif,最多 3 张、单张 ≤ 2MB;缩略图可逐张删除
3. 打开你需要发送的开关:
   - **首次沟通后自动发送图片** —— 打完招呼紧接着发图
   - **HR 提到「简历」时发送图片** —— HR 说「发份简历」时自动发图
4. 图片会**按顺序逐张**作为图片消息发出

> ⚠️ 注意:这里发的是**聊天里的图片消息**,和上面的「附件简历」是两回事 —— 附件简历走的是 BOSS 的「发简历」按钮,图片走的是上传控件。两者可以同时开启。
> 图片功能走的是「注入文件到页面上传框」的路径,属于浏览器允许的做法,但相比纯文字点击更依赖页面结构;如果发不出去,去 **设置 → 诊断页面** 看 `input[type=file]` 那几行日志。

### 四、看效果

- **首页 → 投递日志**:实时滚动显示「公司 · 职位 · 时间」,成功带绿色对勾
- **数据统计** Tab:累计成功数、今日数、成功率,近 7 日柱状图与状态分布

> 说明:「投递」与「沟通」是两个独立入口,分别对应「职位列表页」和「聊天页」。在职位页点「立即沟通」后会弹「留在此页」,扩展会自动点掉;招呼语则在聊天页统一发送。

## 原理(便于自行调整)

所有选择器集中在 `common/constants.js` 的 `HT_SEL` 里,页面改版时只改这里即可。

| 环节 | 选择器 |
|---|---|
| 职位卡片 | `li.job-card-box`(推荐页)/ `li.job-card-wrapper`(搜索页),另含 `.job-name → 卡片` 兜底 |
| 职位名 / 工作地 | `.job-name` / `.job-address-desc,.company-location,.job-area` |
| 猎头标签 | `.job-tag-icon`(alt 含「猎头」) |
| 招聘者状态 | `.boss-online-tag`(在线)、`.boss-active-time` |
| 沟通按钮 | 卡片内 `a.op-btn-chat`;若无则点卡片后用右侧详情面板 `.job-detail-box .op-btn-chat` |
| 留在本页弹窗 | `.default-btn.cancel-btn`(文本「留在此页」) |
| 聊天列表项 / 头像 | `ul[role="group"] li[role="listitem"]` / `.figure` |
| 消息容器 / 对方消息 | `.chat-message .im-list` / `li.message-item.item-friend` |
| 输入框 / 发送 | `#chat-input` / `.btn-send` |
| 发简历 | `.toolbar-btn`(文本「发简历」)、`ul.resume-list li.list-item`、`button.btn-v2.btn-sure-v2.btn-confirm` |

文件结构:

```
manifest.json         扩展清单(权限、注入规则)
background.js         后台 Service Worker(工具栏图标、今日计数徽标、跨天复位)
common/constants.js   共享常量 + 全部页面选择器(HT_SEL)
content/app.js        内容脚本:面板 UI + 投递引擎 + 沟通引擎
content/app.css       面板样式
icons/                扩展图标 16 / 48 / 128
```

## 常见问题

**Q:多个关键词怎么写?空格算不算分隔?**

算。『职位名包含』和『工作地包含』两个输入框都支持以下分隔符:

- 英文逗号 `,` / 中文逗号 `,`
- 换行(回车)
- **空格**(含全角空格)
- 分号 `;` `;`、顿号 `、`

例如工作地填 `杭州 长沙` 或 `杭州,长沙` 或分两行,都会被识别为「杭州 **或** 长沙」两个条件,命中任一即可。

> ⚠️ 注意:因为空格也算分隔,带空格的职位名(如 `AI Agent`)会被拆成 `AI` 和 `Agent` 两个词,按「**任一命中**」匹配,范围会变宽。若想精确匹配带空格的整词,用英文逗号分隔多组,或只填核心词(如 `agent`)。

**Q:点「开始投递」后提示「筛选后待投递 0 个」/「识别到 0 个职位卡片」?**

- 先看日志里这一行:`页面识别到 N 个职位卡片(选择器)`。
  - **N = 0**:卡片没被识别到 —— 页面结构可能变了。点日志页的「**诊断**」,它会打印当前 URL、每个候选选择器的命中数量、首个卡片的 class 与文本,据此就能定位新的选择器。
  - **N > 0 但筛选后为 0**:是 **筛选条件** 把职位都过滤掉了 —— 检查「职位名包含 / 工作地包含」是否填得太窄,或「招聘者活跃状态」只勾了很少见的项(比如只勾「在线」)。把条件清空再试。
- 本扩展同时支持 **推荐页**(`/web/geek/jobs`)和 **搜索结果页**(`/web/geek/job?query=...`)。
- 扩展更新过之后，**必须做两步**，少一步都不生效：
  1. `chrome://extensions` → 点扩展卡片上的 **刷新（↻）**
  2. **回到 BOSS 页面按 `F5`**（已打开的页面里，旧的内容脚本会一直活着）

  三个「已生效」的确认信号：面板标题的版本号（当前 **`v1.0.10`**）、**设置 → 维护** 里有 **复制日志** 按钮、按 `F12` 能在控制台看到 `[一键投 Boss] v1.0.10 内容脚本已加载`。运行日志的第一行也会带版本号。

**Q:薪资筛选怎么用?为什么有的职位被跳过了?**

薪资筛选的工作原理是「**从卡片里读出薪资文本 → 解析成 K/月区间 → 和你的区间求交集**」。因此有三点要清楚:

1. **只有区间有交集才保留。** 你设 15K—60K+，那么 `10-20K` 保留、`8-12K` 跳过、`80-100K` 也保留（因为上限拖到最右时按「60K+ 不设上限」处理）。
   - 运行日志第一行就会写清**本次实际生效的边界**，例如 `薪资条件 15K — 不限(60K+) (区间有交集才保留)`。
   - 每个被薪资刷掉的职位还会**写明原因**，例如：
     `✕ 薪资不符:AI测试工程师 · 15-25K · 25K 低于下限 31K`
   - 所以「明明该保留却被跳过」不用再猜：**先看这两行里的边界是不是你想要的**。

**薪资滑块怎么用（重要）**

面板上的两个滑块是**叠在一起**的（只有圆点本身可拖），所以：

- **右滑块 = 上限。** 想表达「15K 以上」，把右滑块**一直拖到最右端**（上方会显示 `60K+`）。
- **左滑块 = 下限。** 只拖这一个滑块是最安全的：往左拖只会改下限，不会影响上限。
- ⚠️ **不要把任意一个滑块拖过另一个。** 当前实现里，拖上限越过下限会把**下限一起拖着往下走**，
  容易把区间整体拖塌（例如下限本来是 31K，拖了几下上限后变成 `10K—14K`）。
  如果发现区间不对，把**右滑块拖回最右端**即可恢复，然后再只拖左滑块。
- 滑块拖歪了日志会立刻告诉你：`薪资条件 10K — 14K(区间有交集才保留)` —— 这一行就是当前生效的边界。
2. **解析不出来的职位会被跳过**(默认策略)。比如「面议」、页面上没显示薪资、或写法极其特殊。这是**刻意的**:宁可少投几个,也不要把 8K 的岗位当成 15K 投出去。
   - ⚠️ 如果你希望「薪资没写明的也投」,告诉我,可以改成放行模式。
3. **如果日志里出现「薪资未识别」数量很大甚至等于全部卡片**,按顺序查三件事:
   1. **先看日志里的「字体反爬」那一行** —— 如果提示 `检测到 N 种 PUA 码位…已停用解密`,就是 BOSS 换了数字混淆方案(最常见原因)。
   2. 去 **设置 → 维护 → 诊断页面**,会打印「薪资识别自检」段落(每个候选选择器命中几个、前 5 张卡片的**薪资原文 + 卡片文本**),以及**首卡片的 DOM 大纲**(逐层列出 tag / class / 文本),据此就能定位薪资挂在哪个节点上。
   3. 把 **设置 → 维护 → 复制日志** 的内容发我即可。若日志里薪资原文形如 `- K`,说明数字被混淆但没标定成功,重点看「字体反爬标定」段落。

**薪资识别做了三层保险**(页面改版时不必急着改代码):

| 层 | 机制 | 作用 |
|---|---|---|
| ① | 已知选择器按优先级逐个试,并校验内容像不像薪资 | 常规情况,最准 |
| ② | **结构扫描**:找任意「文本很短且像薪资」的元素 | class 名整个换掉也能找到 |
| ③ | 整个卡片文本里抠一段 | 兜底 |

另外,如果 `getCards()` 命中的元素只是卡片的一半(标题块),会自动**向上冒泡**补齐到同时含薪资的父节点 —— 但**只在父节点仍然只含一个职位名时才会冒泡**,避免读到隔壁职位的薪资。

**⚠️ 字体反爬(数字被混淆成不可见字符)**

BOSS 把薪资里的数字 `0-9` 换成了 **Unicode 私用区(PUA)码位**,再用自定义字体渲染回数字。肉眼看到的是 `15-25K`,但 `textContent` 里数字是**消失**的 —— 这就是「薪资筛选完全没用」的真正原因。

判断方法:诊断日志里会出现 `- K`、`- K· 薪` 这种**只有符号没有数字**的残缺文本。

处理方式:插件在解析薪资**之前**先做一次「就地标定」——

```
① 只从薪资节点采样(绝不扫全页:图标字体同样占用私用区,扫全页会把图标码位混进来)
② 枚举所有可能的起始码位,用「解出来得像正经薪资」打分,选得分最高的那一个
③ 校验:混在薪资节点里的混淆字符必须被「全部」解掉;数字不能有前导 0(「04K」不合法);月薪不能是 0 或 >500K
```

**任何一步不通过就停用解密并明确告知** —— 宁可报「薪资未识别」让你去手动确认,也不能把 8K 算成 20K 投出去。

诊断日志的「字体反爬标定」段落会打印:

```
———— 字体反爬标定 ————
  采样薪资节点 N 个
  顺序映射已启用:数字 0 = U+E031 … 9 = U+E03A(已观测 10 种,命中 10 种,校验通过 4 条)
  首卡解码前码点: {E032}{E036}-{E033}{E036}K
  首卡解码后文本: 「15-25K」
```

如果显示 `薪资节点里没有 PUA 字符`,说明页面没启用反爬,那薪资读不到就是别的原因(继续看下面的三层识别)。
如果显示 `检测到 N 种 PUA 码位…但没有任何一种映射能解出合理薪资 —— 已停用解密`,说明 BOSS 换加密方案了,把这行发我。

也可以自己跑一遍解析回归测试(不需要开浏览器):

```
node tools/test-salary-parse.js    # 69 个解析 + 冒泡 + 字体反爬用例
node tools/test-salary-filter.js   # 34 项筛选断言(含字体反爬端到端、日志自解释)
```

两个脚本直接从 `content/app.js` 抽取真实代码执行,不是复制一份。

**Q:图片发不出去?**

1. 先确认你在 **聊天页**(`/web/geek/chat`)—— 图片只能在聊天里发。
2. **设置 → 诊断页面**,看这几行:
   - `input[type=file] 共 N 个` —— 如果 N = 0,说明 BOSS 用的是拖拽上传而不是文件输入,请把日志发我。
   - `图片上传入口 → accept=…` —— 如果显示「未找到」,说明候选选择器需要按你的页面调整。
3. 若上传框找到了但没发出去,可能是 BOSS 要求上传完成后再点一次发送;把「运行日志」里 `发送图片 x/y` 之后的内容发我。

**Q:图片和附件简历有什么区别?**

| | 附件简历 | 图片 |
|---|---|---|
| 走什么 | BOSS 的「发简历」按钮,发送你在 BOSS 已上传的简历 | 上传控件,把你电脑上的图片发出去 |
| 前提 | 必须在 BOSS 上传过附件简历 | 没上传过附件简历也能发 |
| 用途 | 常规投递 | 图片简历、作品截图、二维码等 |

**Q:面板挡住页面了 / 想挪个位置?**

按住面板标题栏(写有「一键投 Boss」的那一行)拖动即可;双击标题栏可一键复位到右下角。位置会自动记住。
